## 项目定位

把移动端变成一个自包含的渗透测试工作台。核心矛盾在于：Android 上的安全工具链几乎都依赖 Linux 环境，而获取 Root 权限会带来设备可用性和风险控制上的代价。

解法是**完全绕开 Root**：用 proot 或 chroot 做用户态文件系统与进程模拟，在不修改内核的前提下跑起一个完整的 Alpine Linux，再在这个用户空间里部署 AI 智能体运行时。

## 关键实现

### 用户态 Linux 运行时

- 通过 `proot` 的 ptrace 拦截机制实现路径重定向，把 Alpine 的根文件系统映射到应用私有目录，规避 Android 运行时的权限限制。
- 处理 ARM64 下的 syscall 差异与动态链接库路径，保证 `apk`、`python3` 等基础工具正常执行。
- 运行时与 Android 应用层通过本地 socket 通信，避免直接暴露 shell 执行入口。

### AI 智能体集成

- 集成 AI 会话与提示词工程模块，把模型能力接到实际的测试任务编排上，而不是停在对话界面。
- 漏洞扫描结果、目标信息、历史会话统一进入上下文，由智能体决定下一步动作。

### 扫描引擎

- **40 线程并发**端口探测，配合 Banner 指纹匹配识别服务类型与版本。
- 支持 **NVD / CNVD 双源漏洞库**自动拉取与本地缓存，扫描结果直接与漏洞库做关联匹配。
- 集成 ADB 与 Root 调试链路，作为设备侧测试的补充通道。

## 工程上的取舍

**性能与功耗的平衡**：移动端 CPU 与散热条件远不如服务器，40 线程是有意压在上限附近的选择——再高会触发降频，实际吞吐反而下降。

**可用性优先于完备性**：免 Root 方案牺牲了一部分底层能力（比如无法监听其他应用的流量），换来的是设备可以直接使用、不需要刷机或解锁，这让工具真正具备随身携带的价值。

**离线可用的底线**：漏洞库支持全量本地缓存，没有网络时依然能完成指纹识别和已知漏洞匹配。
