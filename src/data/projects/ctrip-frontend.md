## 项目内容

携程前端训练营大作业，做一个多端一致的旅游日记平台。

**移动端**：Expo + Gluestack 开发旅游日记 App，包含首页游记瀑布流、搜索、分页加载、详情页，以及"我的游记"的增删改查完整闭环。

**Web 端**：React + Vite 实现浏览器版本，与移动端共用同一套接口和数据模型。

## 多端一致性怎么落地

跨平台开发的难点不在写两遍界面，而在**把平台差异收敛到少数几个点上**。

- 业务逻辑、状态管理、数据请求全部抽成共享层，两端只是不同的渲染出口。
- UI 交给 Gluestack 的跨平台组件承担，它内部处理了 iOS / Android / Web 的样式差异，避免手写大量条件分支。
- 平台特有的东西——状态栏、返回手势、滚动容器——单独隔离，不污染公共逻辑。

选 Expo 的原因也很实际：训练营周期短，Expo 省掉了原生环境配置环节，能直接产出可运行的多端产物。

## 鉴权实现

接入 JWT 完成登录态管理：登录后拿到 token，请求统一携带，服务端校验过期时间与签名。同时做了失效处理——token 过期时清理本地状态并回到登录页，而不是让请求静默失败。

## 踩过的点

**列表页的请求竞态**：搜索框每次输入都发请求，后发的请求可能先返回，把正确结果覆盖掉。处理方式是给每次请求打序号，只接受最新一次的结果。

**瀑布流的高度抖动**：图片没有预占位时，加载完成会引起整列重排。后来改成按已知宽高比先占位，加载完成只做填充。
